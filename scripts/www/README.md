# 客观题库 · C语言 刷题

从扫描版试卷整理出的 C 语言客观题刷题页，纯 HTML/CSS/JS，无依赖，手机优先。

## 运行

任选一种：

- 本地直接双击 `index.html`（file:// 下 localStorage 也能用，但部分浏览器会限制）
- 起一个静态服务（推荐，手机可访问）：
  ```
  python -m http.server 8765 --bind 0.0.0.0
  ```
  电脑：http://127.0.0.1:8765/
  手机（同一 WiFi）：http://<电脑局域网 IP>:8765/
- 想在手机上「添加到主屏幕 + 断网可用」，用自带脚本起 HTTPS：
  ```
  python -m pip install cryptography   # 只第一次需要，用来生成证书
  python serve.py                      # https://<局域网 IP>:8443/
  ```
  首次运行会在 `certs/` 下生成一套本地 CA 与证书（`ca.cer` 是要装到手机上的那个）。
  只想用 HTTP 时加 `--http`，换端口用 `--port 9000`。

## 手机安装 / 离线使用

Service Worker 只在**安全上下文**里可用：`http://127.0.0.1` 可以，`http://<局域网 IP>` 不行。
所以手机要离线，必须走 HTTPS：

1. 电脑上 `python serve.py`，记下打印出来的 `https://<局域网 IP>:8443/`
2. 把 `certs/ca.cer` 传到手机（微信 / QQ / 数据线都行），装成根证书
   - Android：设置 → 安全 → 加密与凭据 → 安装证书 → CA 证书 → 选 `ca.cer`
   - iOS：安装描述文件后，还要去 设置 → 通用 → 关于本机 → 证书信任设置 打开完全信任
3. 手机浏览器打开 `https://<局域网 IP>:8443/`，菜单里选「添加到主屏幕」
4. 之后从桌面图标进入是全屏的；第一次加载过以后断网也能做题（题库和页面都在缓存里）

不想装证书也可以只用 `http://<局域网 IP>:8765/`：页面能用，但没有 Service Worker，
不能离线，也没有全屏图标。

## 文件

| 文件 | 作用 |
| --- | --- |
| `index.html` | 页面骨架，只做容器 |
| `style.css` | 「纸上机考」视觉：纸白、墨黑、答题卡气泡、评卷印章 |
| `app.js` | 全部逻辑：出题、判分、错题本、模拟考试、统计、localStorage |

| `serve.py` | 本地 HTTPS 服务（自签 CA + 证书），手机离线就靠它 |

## 功能

- **今日练习**：按日期抽 20 题（判断 10 + 选择 10），同一天反复进来都是同一份
- **顺序练习**：从第一道没做的题开始，往下一口气做 N 题（N 自己定）
- **专项练习**：判断题 / 选择题分开练，每组题量自己定
- **模拟考试**：判断 + 选择各半，题量自己定，倒计时按每题 1.5 分钟算（最少 5 分钟、最多 180 分钟），到点自动交卷
- **章节练习**：按章节挑题，可多选，题量自己定；选择页可切「混合 / 只判断题 / 只选择题」，上次的选择和题型会记住
- **错题本**：答错自动收录，重做答对自动移出；「错题重做」固定把错题全部过一遍
- **统计**：掌握度圆环、正确率、连续答对、分题型进度、分章节掌握度（默认收起）、最近模拟考
- 题号旁的章节（如「第 8 章 · 指针」）显示在解析栏底部；章节练习时题头会标出已选章节
- 键盘 1–4 / 方向键切题，手机上点选项即判

### 本次题量

除「今日练习」（固定 20 题）外，点模式卡会先弹出「本次题量」面板：− / + 步进、滑杆拖动，
或直接点 10 / 20 / 50 / 全部 N 题。上限就是该模式的题池（模拟考试上限 296 题 = 判断 148 + 选择 148），
每个模式各自记住上次的题量（「全部」也记住，开跑时按当时题池换算）。超过 40 题时不再显示答题卡小圆点条。


## 章节归类

10 章按《C 语言程序设计》常见章节划分：基础知识、顺序结构、选择结构、循环结构、函数、
存储类型和预编译、数组、指针、结构体、文件。每题只归一个主章节，跨章题按「考察重点」归主章。

归类流程：4 个并行标注任务各标 102/102/102/99 题 → 与关键词规则交叉比对（122 条冲突逐条看过）→
人工复核 40 余题后写 `chap/overrides.json` 覆盖 17 题（printf/scanf 格式符与输入输出类，从「基础知识」移到「顺序结构」）。

| 章节 | 合计 | 判断 | 选择 |
| --- | --: | --: | --: |
| 1 基础知识 | 63 | 33 | 30 |
| 2 顺序结构 | 22 | 6 | 16 |
| 3 选择结构 | 28 | 16 | 12 |
| 4 循环结构 | 75 | 62 | 13 |
| 5 函数 | 36 | 28 | 8 |
| 6 存储类型和预编译 | 16 | 13 | 3 |
| 7 数组 | 59 | 32 | 27 |
| 8 指针 | 58 | 34 | 24 |
| 9 结构体 | 24 | 20 | 4 |
| 10 文件 | 23 | 12 | 11 |

「顺序结构」只有 22 题，是因为这份卷子里「赋值 + printf 求输出」的整段程序题本来就少，
与之相关的格式符题按考察重点放进了顺序结构；其余大多是概念判断题。

## 数据来源与缺口

原文件 `客观题库--测试.pdf` 是扫描件（130 页，无文字层），转出的 Word 由逐字定位拼接而成，
存在代码换行丢失、选项以图片形式存在等问题。处理流程：

1. `extract.py` 解析 Word，用「答题卡 ◎ 填涂」+「参考答案表」两路信号互相校验
2. `polish.py` 定点修补确认的 OCR 损伤（见文件内 `REPAIRS`）
3. `build.py` 合并解析结果、解析文字与章节标注，生成 `data.js`

最终收录 **404 题**（判断 256 + 选择 148）；另有 **15 题**未收录，记录在 `blocked.json`：
13 题选项文字在图片里无法还原，`1-148` 题干丢失，`2-146` 只剩「*字符数组(1-3)」无从作答。
说明页里如实标出这两个数字。

## 数据流水线（需要重新生成时）

```
python extract.py    # docx -> questions.json + blocked.json
python polish.py     # 定点修补 + 丢弃无法作答的题
python build.py      # 合并章节与解析 -> data.js
```

`expl/p*.json` 是每题一句话解析，`chap/p*.json` 是章节标注，`chap/overrides.json` 是人工复核覆盖
（`chap/overrides.why.json` 记录覆盖理由）；`build.py` 会校验题号与解析一一对应。
`_dev/phone.html` 是开发用真机宽度（390px）预览壳，不参与线上页面。
